# AHDG-0002 — No cross-layer authority forge found (bounded assurance)

| Field | Value |
|---|---|
| ID | AHDG-0002 |
| Type | negative result / bounded assurance (not a bug) |
| Layer | ISO-TP × UDS (cross-layer) |
| Invariants | XL-1, XL-2, TP-1, SEC-1..4, AVAIL-2 |
| Instrument | `fuzz/ahdg_frames.c` — frame-level adversarial explorer |
| Status | open, re-checked every CI run |

## What was tested

The frame-level adversary composes sequences of real CAN frames — Single,
First, Consecutive (correct and wrong sequence number), Flow Control,
invalid-PCI, interleaved First Frames, and N_Cr clock jumps — and injects them
into the **real** `isotp_rx` + `uds` pipeline, exactly as the ECU receives them.
After each hostile sequence a *golden probe* (two valid requests) checks that the
ECU still answers correctly.

It searches specifically for the cross-layer failure the project is about: a
transport-level manipulation (ISO-TP desynchronization) that makes the UDS layer
grant authority it should not, or a hostile sequence that leaves the ECU unable
to serve a legitimate request afterwards (denial of diagnostic).

## Result

| Campaign | Sequences | Frames injected | Messages reassembled | Counterexamples |
|---|---:|---:|---:|---:|
| seed 0xF00D | 1,000,000 | 10,497,978 | 5,651,498 | 0 |
| seed 0x5A5A | 1,000,000 | 10,514,107 | 5,660,734 | 0 |

Zero counterexamples for XL-1, XL-2, TP-1, SEC-1..4 and AVAIL-2 across **21
million adversarial frames** on two independent seeds, under
AddressSanitizer + UBSan.

## Why this holds — and why it is only bounded assurance

The ISO-TP receiver resets to a defined state on **any** anomaly — a wrong
sequence number, an interleaved transfer, an overflow, a timeout — and only ever
emits a fully, in-order reassembled message to the UDS layer. A transport
desynchronization therefore cannot deliver a partial or spliced message that the
UDS server would act on: the authority-forging path does not exist by
construction of the reset discipline. The golden probe further shows the ECU is
never wedged: a valid Single Frame always resets any pending transfer and is
served.

This is **evidence, not proof**. The adversary explores; it does not enumerate.
It covers this action alphabet and these two seeds, not every possible frame
interleaving. The result is recorded as a bounded assurance and re-checked on
every CI run (`make frames`), so a future change that opened a cross-layer hole
would fail the build.

## Significance

This is the first experimental support for the cross-layer (XL) claims. It says:
on the current stack, the transport layer cannot be used to forge UDS authority
or deny the diagnostic service, over 21M adversarial frames. When the in-line
gateway mediation (M53) and additional services land, the same instrument will
re-run against the larger surface.

## Reproduce

```bash
make frames                    # 300k sequences, seed 0xF00D
./build/ahdg_frames 1000000 0x5A5A
```
